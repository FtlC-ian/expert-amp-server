Safety Monitoring

Evaluates protocol-native temperature and SWR readings. Monitoring is observational by default. Active standby requires a separate explicit opt-in and sends one state-gated OPERATE command; it never navigates menus, acts during TX, powers off, retries, or turns the amplifier back on.

Match the temperature unit selected in the amplifier's SET menu. The status protocol sends numbers without a unit. Safety and automatic fan thresholds below always remain Celsius.

The warning value must be lower than the trip value. Reset must be below trip; when unset, warning is used. The hottest available upper, lower, or combiner sensor is evaluated. A trip requests STANDBY only when fresh protocol status explicitly reports OPERATE and RX. If automatic fan cooling is enabled, its high threshold must remain below this trip threshold. The toggle remains sent/unconfirmed because the protocol cannot correlate its response. It never retries or auto-wakes.

SWR is evaluated only while TX is active, using the higher available ATU-side or antenna-side reading. SWR remains observational and never actuates the amplifier.

Automatic Fan Cooling

Experimental and disabled by default. Automatic fan cooling requires a promoted hardware profile and supports the verified First Series Expert 1.3K-FA and CONFIG-first Second Series Expert 1.5K-FA paths. Unsupported models are blocked before SET; use Menu Debug to capture candidate profiles. During a transaction the server verifies the model, first menu topology, and every later waypoint, waits for RX, temporarily changes OPERATE to STANDBY when necessary, and restores OPERATE only when it owned that change.

Requires Polling mode Both and at least 5 °C between thresholds. We recommend testing Fan Boost before enabling automatic mode. Menu entry, fan changes, and SAVE are RX-only. Any unexpected screen or failed write stops the transaction. To clear a failed transaction, stop transmitting, put the amplifier in STANDBY, return to its home screen with the physical panel, disable automatic fan policy, then use Clear Failed Fan Transaction.
