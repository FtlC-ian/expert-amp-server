# v0.5.0 documentation audit

Scope: all tracked human-facing documentation, embedded help/API documentation, configuration/install/release examples, and evidence metadata, checked against main `a0d0155fc64cafd482db0f9ff4b998855eb63ea4` plus this documentation-only preparation. This inventory records review, not hardware requalification. Publication is deferred until independent review and maintainer authorization.

## Structural boundaries

- `/api/v1` remains the public route contract; OpenAPI is hand-maintained and embedded, not generated. Release version is injected into `main` by the packaging script; development defaults remain `dev`.
- Runtime display arrival and content clocks are separate. Contact/provenance cannot replace native freshness, model/session binding, or action-specific actuation gates.
- Raw TCP is an exclusive byte-stream lease, not a protocol/control proxy. Armed automatic fan control or overtemperature standby blocks admission; lease-held arming is refused. Listener changes require restart.
- Store publication, subscriber removal, and channel closure share a lock. No runtime, feature, test, captured fixture, or service configuration was changed by this preparation.
- Existing historical release claims and fixture firmware/server versions remain historical evidence, not current-version settings.

## Verification boundaries and follow-ups

Release receipts (frozen SHA, toolchain, commands, output, architecture metadata, SHA256SUMS, and loopback fixture-only HTTP smoke results) are retained outside tracked source under the dedicated checkout's ignored `dist/evidence/` and `dist/v0.5.0/`. See `READINESS.md` for exact commands. Offline full-suite/race/vet/build checks are regressions, not claims of a new physical installation or RF safety validation.

OpenAPI checks cover JSON syntax, all local references, and the canonical route inventory. There is no configured third-party semantic validator or release CI in this checkout. Linux/systemd install and browser/Node-RED runtime operation were not exercised on a target host. No signing convention exists in the latest release.

Code-adjacent observations are deliberately not fixed here:

- The display stream decoder still initially searches the historical eight-byte prefix before recognizing the complete GetLCD shape; alternate low flag bytes remain a documented capture/decoder gap.
- `DecodeTextChar` (legacy screen text) and accessible display text intentionally have different mapping/alternate-bank treatment; the corrected protocol table describes each decoder's implementation, not a broad model glyph guarantee.
- The build helper's artifact glob includes stale files if the output directory is reused; the release procedure now requires an empty dedicated directory.
- Local API docs render response `$ref` entries without resolving their referenced response content, so some schema previews say no content schema despite defined responses. This is a pre-existing renderer limitation, not an absent API response contract; independent reviewer may schedule a focused code/test follow-up.
